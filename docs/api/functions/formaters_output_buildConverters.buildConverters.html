    • buildConverters<
          E extends { active: boolean; created: Date; id: number; updated: Date },
      >(
          metadata: EntityMetadata<E>,
          converters: ConverterFunctionsBuild,
          depth?: number,
      ): ConverterFunctionsInfer<E>

      Build a complete set of attribute converters for an entity and its nested relations.

      Takes the type-keyed ConverterFunctionsBuild (one function per AttributeTypes entry, plus aggregate-function operators) and the entity's EntityMetadata, and produces a ConverterFunctionsInfer where every base attribute and every relation attribute has its concrete converter function bound to it.

      Build steps:

      1. Base attributes — for every entry in metadata.baseAttributesList, look up the converter registered for that attribute's declared type in converters.baseAttributes. Attributes whose type has no registered converter are silently skipped (no entry is created).
      2. Relations — for every entry in metadata.subEntities, recurse into buildConverters with depth + 1 so the related entity gets its own converter tree. Recursion is capped at depth 5 (inclusive) to bound the type-level expansion.
      3. Aggregate functions — only at depth 0 (the root entity), copy converters.fns into the result. Deeper levels never carry aggregate converters, since aggregate functions are valid only at the root of a query.

      Type Parameters

      • E extends { active: boolean; created: Date; id: number; updated: Date }

        Entity whose metadata drives the converter set.

      Parameters

      • metadata: EntityMetadata<E>

        Entity metadata providing baseAttributesList, attributesConfig, and subEntities.

      • converters: ConverterFunctionsBuild

        Type-keyed converter definitions (built once per dialect) that get bound to specific attribute names here.

      • depth: number = 0

        Current recursion depth. Defaults to 0 (root call). Each sub-entity recursion increments this by one. Hard-capped at 5 — deeper relations are skipped to keep the type tree tractable.

      Returns ConverterFunctionsInfer<E>

      A ConverterFunctionsInfer<E> with:

      • baseAttributes — converters keyed by attribute name;
      • subEntities — recursively built converters keyed by relation key;
      • fns — aggregate-function converters, included only at the root level.

      Example

      const converters = buildConverters(productMetadata, mysqlConverters)

      converters.baseAttributes.brand   // (v: string) => string
      converters.subEntities.prices     // nested ConverterFunctionsInfer<Price>
      converters.fns?.$count            // (v: number) => number  (root only)
